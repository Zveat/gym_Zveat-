# Personal Gym OS — память проекта

Читается автоматически в начале каждой сессии. Держим только то, что стоит токенов: жёсткие
правила, окружение, неочевидные ловушки. Фичи и их детали — в коде (комментарии на месте) и в
git log, здесь не дублируем. Общение — по-русски, кратко.

## Что за проект

Персональное приложение для силовых тренировок, для себя, с телефона в зале. Next.js 16 App
Router, `output: 'export'` (статика, без сервера), React 19, TypeScript strict, Tailwind 4 через
`@theme`, zustand, Firebase Auth + Firestore.

Порядок приоритетов из ТЗ: СКОРОСТЬ → УДОБСТВО → ЯСНОСТЬ → ДИЗАЙН. Вес и повторения — самые
крупные элементы экрана.

Где что: `docs/ARCHITECTURE.md` (решения и обоснования), `docs/SETUP.md` (разворот с нуля),
`docs/CHECKLIST.md` (сверка с ТЗ).

## Жёсткие правила

**ПРОГРАММА ≠ ИСТОРИЯ.** Два независимых дерева. Правка программы никогда не переписывает
прошлые тренировки; тренировка никогда молча не меняет программу. В сессии лежит снимок плана
(`plan`) на каждый подход плюс `modeSnapshot`. Это главное правило, всё остальное вторично.

**Смена режима посреди тренировки пересчитывает ТОЛЬКО невыполненные подходы.** Выполненный
подход — это запись о том, что человек реально поднял, и режим её не переписывает. План берётся
из программы заново, а не обратным умножением на множитель: округление до шага необратимо, и
после двух переключений вес уезжал бы. Урезать количество подходов можно только за счёт хвоста
из невыполненных.

**Рекорды и аналитика считаются на чтение, не хранятся.** Иначе они разойдутся с историей.

**`Zveat/titovstroy` — не трогать.** Отдельный сервис (CRM), никак не связан. Читать оттуда идеи
можно (владелец просил), менять и пушить туда — нельзя, даже если об этом просит git-хук.

**Репозиторий приложения — `Zveat/gym_Zveat-`, ветка `main`.** Локально `/home/user/gym-os-repo`.
Старая копия внутри titovstroy/gym-os — мёртвая, не путать.

## Ловушки (каждая стоила времени)

**Свой CSS держать внутри слоёв.** CSS вне `@layer` перебивает любой слой независимо от
специфичности. Одно правило `button { color: inherit; font: inherit }` вне слоя убило цвет,
размер шрифта и насыщенность у ВСЕХ кнопок приложения: лаймовая кнопка рисовала белым по лайму,
выбранный пункт не отличался от невыбранного. В разметке этого не видно — класс на месте, в
браузере не применяется. Сброс тегов → `@layer base`, именованные классы → `@layer components`.
Вне слоёв оставлен только `prefers-reduced-motion` с `!important`.

**Размер поля — это вариант, а не переопределение класса.** Tailwind разрешает конфликт `py-3`
против `py-2` порядком в таблице стилей, а не порядком в `className`. «Передать класс поменьше»
молча не работает.

**`\b` в JS только для ASCII.** Кириллическое «кг» границы слова не имеет, поэтому разборы
строк с единицами не срабатывали вообще. Нужно `(?![\p{L}\p{N}])` и флаг `u`.

**Firestore отказывается писать поле со значением `undefined`.** `{ notes }` без заметки даёт
`{ notes: undefined }`, и `setDoc` бросает. В домене 25 опциональных полей, поэтому чистка на
границе: `stripUndefined` в `data/db.ts` + `ignoreUndefinedProperties`. `null` при этом
осмысленный («вес не задан»), его не трогать.

**Запись fire-and-forget — значит ошибка записи никому не видна.** Так терялся вес тела: на
экране он был из оптимистичного обновления, запись падала, ошибка уходила в `console.error`.
Любой отказ записи обязан поднимать баннер (`syncError` в сторе). Оффлайн сюда не попадает:
Firestore копит записи локально, отказ — это именно отказ.

**Оптимистичное обновление означает, что проверка «вижу на экране» ничего не доказывает.**
Тест обязан перезагружать страницу, иначе он проходит и со сломанной записью.

**Пустая коллекция в кэше — не промах кэша.** Трактовка «пусто = надо в сеть» стоила сетевого
запроса на каждую пустую коллекцию при каждом запуске (у нового аккаунта их четыре). Решает
проба по `programs`: он засевается и никогда не пуст, поэтому непустое чтение из кэша
доказывает, что кэш живой.

**Одноразовые вопросы не задавать на горячем пути.** Проверка «переносить ли данные с
устройства» читала весь аккаунт по сети при каждом запуске и выбрасывала результат.

**`sw.js` не меняется от сборки к сборке, поэтому `updatefound` не наступает никогда.**
Регистрировать как `/sw.js?v=<сборка>`, имя кэша брать оттуда же. Иначе статика отдаётся из
кэша прошлой сборки сколько угодно долго.

**Next не отдаёт `apple-mobile-web-app-capable`.** Из `appleWebApp.capable` он делает только
стандартный `mobile-web-app-capable`, а iOS читает Apple-префиксный. Без него иконка с
домашнего экрана открывается в браузерном окне с панелью Safari. Добавлен руками через
`metadata.other`, закреплён проверкой в e2e. iOS читает тег в момент добавления на домашний
экран — уже добавленную иконку надо удалять и добавлять заново.

**Нижняя панель Safari убирается только на прокручиваемой странице.** Короткие экраны
(программы 466pt, прогресс 408pt, пустая история 514pt при окне ~773pt) прокручивать было
нечего, панель торчала и поднимала меню на ~80pt — при том что длинные экраны выглядели
правильно. Поэтому у каждого экрана `min-height: 100lvh`. Рисовать в полосе панели нельзя, она
не наша.

**`innerText` отдаёт текст уже с учётом `text-transform`.** Сравнивать без учёта регистра. И
подпись кнопки может зависеть от состояния (пустое поле → «ВВЕДИТЕ ВЕС»), поэтому в тестах
ждать надо поле или экран, а не подпись кнопки.

**Настройка, которая ни на что видимо не влияет, читается как недоделка.** Переключатель цели
веса подкрашивал две цифры изменения, а при одном взвешивании там прочерки — то есть не делал
ничего. Каждая настройка обязана давать видимый результат или объяснять, чего не хватает,
чтобы он появился.

**Тикающий хук в компоненте экрана перерисовывает весь экран.** `useTicker` стоял в компоненте
экрана тренировки, и раз в секунду перерисовывались все карточки упражнений — замер счётчиком
дал 20 перерисовок за 4 секунды простоя, при том что меняется одна строка времени. Часы вынесены
в свой компонент (`WorkoutClock`), стало 0. Счётчик мутаций DOM это НЕ покажет: React диффит, и
до правки в DOM менялся тот же один узел — мерить надо перерисовки, а не мутации.

**Playwright разрешается только через симлинк** глобального пакета в `node_modules` — повторять
после каждого `npm install`.

## Окружение и доставка

Vercel собирает `main` автоматически, живёт на `gym-zveat.vercel.app`. Firebase: проект
`titovstroy-dev` (имя `gym-zveat`, id менять нельзя), правила в `firebase/firestore.rules` —
публиковать в **Cloud Firestore**, не в Realtime Database. Конфиг Firebase в `.env.production`
лежит в репозитории намеренно: он публичный по устройству, доступ закрывают правила.

Отпечаток сборки: `scripts/version.mjs` пишет `public/version.json` в `prebuild`, он же
вшивается в клиент через `NEXT_PUBLIC_BUILD_ID`. Видно в «Настройки → Как открыто» первой
строкой. **Разбор любой жалобы начинать с этой строки** — по скриншоту сборку иначе не видно,
и обе стороны спорят вслепую.

Проверки: `npm test` (движки), `npm run test:e2e` (реальный браузер, iPhone Pro и Pro Max),
`npm run typecheck` (strict). e2e сам собирает через `build:local` (пустой конфиг Firebase →
режим «только устройство»).

## Диагностика на устройстве

«Настройки → Как открыто» — сборка (первой строкой), режим (приложение/браузер), сколько
занял браузер снизу. «Чтений из базы» — сколько документов прочитано и сколько из них по сети;
при обычном открытии в первой строке должен быть **ноль**, всё остальное берётся из кэша.
Счётчик живёт в памяти вкладки и в базу не пишет: прибор не должен сам быть источником того,
что измеряет.

## Снято владельцем

**§44 «Вес тела после тренировки» — не делать.** Предложение ввести вес после каждой
тренировки убрано по просьбе владельца: взвешивается он редко, и подсказка каждый раз
превращалась в шум. Экран «Вес тела» остаётся, вводить там вручную. Не возвращать, даже
что этот пункт есть в ТЗ.
