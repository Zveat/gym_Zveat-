# Personal Gym OS

Персональная операционная система для силовых тренировок. Mobile-first PWA:
программа живёт в приложении, а не в заметках, история пишется сама, прогресс
считается из истории.

В любой момент приложение отвечает на четыре вопроса:

1. Что мне делать сейчас?
2. Какой вес использовать?
3. Что я делал в прошлый раз?
4. Есть ли у меня прогресс?

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:3000
```

При первом запуске создаётся текущая программа пользователя — сплит на 5 дней
с реальными весами, диапазонами повторений, настройками тренажёров и личными
заметками. Можно идти в зал сразу.

```bash
npm run build      # статический экспорт в ./out
npm run typecheck
npm test           # 94 теста на чистую логику
npm run test:e2e   # 106 проверок в реальном браузере (нужен playwright)
```

`npm run test:e2e` требует Playwright и Chromium. Если они установлены
глобально, достаточно `PLAYWRIGHT_BROWSERS_PATH=… node e2e/smoke.mjs` после
`next build`.

## Что внутри

| | |
|---|---|
| Фронтенд | Next.js 16 (App Router), React 19, TypeScript, Tailwind 4 |
| Состояние | zustand — одно хранилище на всё приложение |
| Данные | IndexedDB на устройстве, с откатом на localStorage |
| Графики | Recharts (линии) и собственные CSS-бары (группы мышц) |
| Доставка | статический экспорт + service worker, работает офлайн |

Сервера нет: `output: 'export'` в `next.config.ts` этого не позволит. Всё
считается на устройстве, поэтому приложение открывается и пишет подходы без
интернета — в зале это норма.

## Главное правило архитектуры

**Программа ≠ история.**

Программа — шаблон. Тренировка — факт. Это два независимых дерева:

```
programs → days → exercises → sets      план
sessions → exercises → sets             факт
```

Тренировка хранит *снимок* плана, по которому её начинали (`plan` у каждого
подхода, `modeSnapshot` у тренировки). Поэтому:

* правка программы не переписывает прошлые тренировки;
* тренировка не меняет программу молча — только через экран Review, где
  пользователь принимает решение сам;
* рекорды и аналитика считаются из истории на чтение, а не хранятся, так что
  исправление опечатки в старом подходе сразу исправляет и рекорды.

## Структура

```
src/
  domain/         модель данных, дефолты режимов, начальные данные
    seed/         библиотека упражнений и текущая программа на 5 дней
  engine/         чистая логика, вся под тестами
    session.ts    сборка тренировки из программы и режима, запись подходов
    progression.ts что делать с весом дальше
    records.ts    рекорды и их обнаружение по ходу тренировки
    analytics.ts  объём, группы мышц, динамика, вес тела
    history.ts    выборки по истории
    import-parser.ts разбор заметок и CSV
  data/db.ts      IndexedDB → localStorage → память
  store/          zustand: состояние, действия, селекторы
  components/     дизайн-система и блоки экранов
  app/            20 экранов (App Router)
e2e/smoke.mjs     сквозной прогон в браузере
```

Подробнее о решениях и их причинах — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Режимы тренировок

`NORMAL` / `LIGHT` / `HEAVY` / `RECOVERY` — это **модификаторы поверх активной
программы**, а не отдельные программы. Отдельную программу под «сегодня
полегче» создавать не нужно.

Все коэффициенты редактируются в настройках. По умолчанию:

| Режим | Вес | Подходы | Повторения | Отказные |
|---|---|---|---|---|
| Normal | 100% | как в программе | как в программе | да |
| Light | 85% | −1 | — | нет |
| Heavy | 105% | — | −2 | да |
| Recovery | 70% | 55% | — | нет |

Перед запуском виден предпросмотр: `50 kg × 12 × 4 → 42.5 kg × 12 × 3`.

## Прогрессия

У каждого упражнения своё правило: `manual`, `double` (двойная прогрессия),
`fixed` (линейная) или `custom`. После тренировки приложение предлагает
решение, а не принимает его.

Боль и сломанная техника перебивают любые цифры: если отмечена боль, вес
предлагается снизить, даже когда цель по повторениям закрыта.

## Данные

Всё хранится на устройстве. Экспорт и восстановление — в настройках;
резервную копию стоит делать перед сменой устройства.

Историю за прошлые месяцы можно внести двумя способами: по одной тренировке
(`/history/add`, план подставляется из программы) или массово — вставить
старые заметки текстом либо выбрать файл CSV или Excel (`/more/import`).
Разбор понимает даты в разных форматах и подходы вида `50 x 12`,
`52,5кг × 10`, `22.5 x 12 x 4`, `50кг 3 по 12`. Ничего не пишется, пока
пользователь не подтвердит предпросмотр.

`.xlsx` читается без сторонних библиотек: файл распаковывается в браузере
(`engine/xlsx.ts`), включая даты, которые Excel хранит числом. Ничего никуда
не отправляется.

У упражнения может быть своё фото — снятое на телефон или из библиотеки.
Оно уменьшается до 1280 px по длинной стороне и хранится вместе с
упражнением, так что резервная копия забирает его с собой.
